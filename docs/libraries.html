📦 What is a ZincLang library?

A ZincLang library is simply a .zc file (or a folder of files) that exports functions, variables, or classes using the export statement. Anyone can import it with import <name>; and access the exported members via the module name.

✅ No special packaging tools needed – a single file is enough. For larger libraries, you can split into multiple files and have one main entry point that re‑exports.

🔧 Creating your own library

1. Write your module

Create a file, e.g., mylib.zc, and define your functions:

// mylib.zc
func greet(name) {
    Print("Hello, " + name + "!");
}

func farewell(name) {
    Print("Goodbye, " + name + ".");
}
export greet;
export farewell;

2. Export what users need

Use the export statement after defining the item:


func add(a, b) { 
    return a + b; 
}
export add;   // now it's visible when imported
⚠️ Order matters: export looks for a name in the current environment. Define your function/variable/class first, then export it.

3. (Optional) Add a manifest zinc.toml

For future package managers (ZPM), you may include a manifest:

[package]
name = "mylib"
version = "1.0.0"
author = "Your Name"
description = "My awesome Zinc library"

[lib]
path = "mylib.zc"   # main entry point

Currently, the manifest is not required; the interpreter only reads .zc files.

📥 Using someone else's library

To use a Zinc library, you need to place its .zc file where ZincLang can find it.

Method 1 – Copy to your project folder

Place the .zc file next to your script, then import:

// main.zc
import mylib;

mylib.greet("Zinc");

Method 2 – Use a lib/ subdirectory

Create a folder named lib in your project root, put libraries there, and ZincLang will automatically find them.

your_project/
├── lib/
│   └── mylib.zc
└── main.zc

Method 3 – Set the ZINC_PATH environment variable

Define a global library folder (e.g., C:\zinc_libs) and add it to ZINC_PATH (semicolon‑separated on Windows).

set ZINC_PATH=C:\zinc_libs

Then any script can import libraries from that folder without copying.

🌐 Sharing your library – The official ZLiP index

We are building the ZincLang Index of Packages (ZLiP) – a central registry. Currently, you can share your library by:

  • Hosting it on GitHub (public or private).
  • Providing a direct download link to the .zc file.
  • Submitting a pull request to the official zinclang_lib repository (once established).

We recommend you create a GitHub repository named zinc-<library-name> (e.g., zinc-math) and include a README.md with usage examples.

💡 Future: ZPM – We plan to release zpm (Zinc package manager) in version 5.x. It will allow zpm install math to automatically download and place libraries.

🧪 Example: Using a real math library

Assume you downloaded math.zc from the official repository:

// math.zc
func add(a, b) { return a + b; }
func mul(a, b) { return a * b; }
func sqrt(x) { return x ** 0.5; }   // hypothetical

export add;
export mul;
export sqrt;

In your script:

import math;
Print(math.add(5, 3));     // 8
Print(math.mul(4, 2));     // 8
Print(math.sqrt(16));      // 4.0

🤝 Contributing to the ecosystem

We welcome community libraries! To publish your library as “official” (listed on this site and in the index), please:

  1. Ensure your library is a single .zc file with clear exports.
  2. Write a short README with installation and usage instructions.
  3. Add a zinc.toml manifest (optional but recommended).
  4. Open a pull request to the zinclang_lib repository (coming soon).

All contributions must follow the Contributor Promise – see CONTRIBUTING.md.
